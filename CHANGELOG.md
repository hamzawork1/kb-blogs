### Added — CI/CD pipeline
- GitHub Actions workflow at `.github/workflows/ci-cd.yml`:
  - **`build` job** — runs on every PR + push to `main`/`staging`. Sets up pnpm 10.27.0 + Node 22, `pnpm install --frozen-lockfile`, `pnpm lint` (Biome), `pnpm build`, asserts Pagefind index exists, uploads `dist/` as a build artifact.
  - **`deploy` job** — only on push to `main` or `staging`. Downloads the artifact and runs `wrangler deploy --env <env> --name <worker-name>` via `cloudflare/wrangler-action@v3`. Uses GitHub Environments (`production` / `staging`) for deploy URL tracking.
- `wrangler.toml` at repo root declaring the `production` (Worker `mhamza-space`) and `staging` (Worker `mhamza-space-staging`) environments with `[assets] directory = "./dist"`.
- Repo secrets configured: `CLOUDFLARE_API_TOKEN` (scope `Workers Scripts:Edit`), `CLOUDFLARE_ACCOUNT_ID`.

### Added — staging environment live
- First successful staging deploy after three iterations (see Fixed below). Worker `mhamza-space-staging` serves the site from Cloudflare's edge.
- Custom domain **`staging.mhamza.space`** attached to the staging Worker; SSL provisioned via Cloudflare.
- Default `.workers.dev` preview URL **disabled** on the staging Worker — only `staging.mhamza.space` reaches it now (privacy + single source of truth + no accidental indexing).

### Fixed (CI iteration log)
The pipeline was rough out of the gate. Three real-world iterations to get green:

1. **Node 22 bump.** First `build` job failed with `Astro 6 requires Node >=22.12.0` — workflow had `node-version: 20`. Pinned to 22 LTS.
2. **Wrangler 4 pin.** First deploy attempt (post-merge) failed because `cloudflare/wrangler-action@v3` installs Wrangler 3.90.0 by default. Wrangler 3 doesn't fully support static-only Workers — it demands a JS entry-point and chokes on `[env.<name>]` blocks that lack one. Added `wranglerVersion: "4"` to the action inputs.
3. **`--name` flag.** The Wrangler-4 deploy succeeded but created a Worker named `kb-blogs-staging` instead of the `mhamza-space-staging` declared in `wrangler.toml`'s `[env.staging].name`. Cloudflare resolved the env-block name against pre-existing project context on the account. Fix: force the name via the CLI `--name` flag, which overrides everything.

Each finding is captured in `docs/runbooks/deploy-cloudflare-pages.md` → "Notes during initial setup" so future-us never relearns it.
